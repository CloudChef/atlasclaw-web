# AtlasClaw B2B Visual Tone Design

**Date:** 2026-03-14

**Goal:** Shift the website toward a steadier B2B visual tone inspired by enterprise product sites, while keeping AtlasClaw's single-product identity and existing light palette.

## Design Direction

AtlasClaw should feel less like a brand showcase and more like a credible enterprise product homepage. The reference is not AWS's multi-product navigation model, but its visual discipline: strong information hierarchy, modular section boundaries, restrained decoration, and higher trust density.

The site will stay light-themed, but the presentation should become more structured:

- sharper section boundaries
- cleaner cards with less atmospheric softness
- more explicit content grouping
- stronger product-summary framing in the hero
- higher consistency in spacing, heights, and card rhythm

## What To Borrow From AWS

- Heavy, confident headings
- Clear section framing
- Modular content blocks that read like product surfaces
- Reduced decorative noise
- Stronger sense of enterprise trust and order

## What Not To Borrow

- Multi-product catalog homepage structure
- Dense service menus or mega-navigation
- Dark enterprise-cloud aesthetic
- AWS-specific orange/charcoal branding cues

## AtlasClaw-Specific Translation

Because AtlasClaw is a single framework product, the homepage should behave like a structured product definition page:

1. Hero defines the product
2. Enterprise comparison explains why it exists
3. Capability sections explain how it fits real systems
4. Architecture and integrations provide proof
5. Docs and GitHub provide deeper entry points

## Hero Panel Guidance

The right-side hero summary should feel like a product summary module:

- keep the icon and summary copy
- keep the capability ribbon
- keep four capability cards
- reduce “floating” feeling
- keep tighter visual grouping
- preserve a stable 2x2 capability grid

The capability ribbon should remain short and concrete:

- Multi-User
- Systems by Skills
- Multi Channels
- Auth by SSO

## Homepage Messaging Guidance

The homepage must explicitly foreground these enterprise differentiators:

- multi-user AI agent deployment
- permission-governed execution
- webhook + skills to empower existing systems with AI
- enterprise-approved model access

This webhook + skills point must appear on the homepage, not only in architecture details.

## Visual Rules

- Use clearer borders and lower-glow surfaces
- Prefer consistent card heights within a group
- Keep shadows soft but more restrained
- Reduce decorative blur dominance
- Make section layouts feel intentionally aligned and product-like
- Maintain accessible contrast and mobile readability

## Scope

This design direction applies to:

- homepage hero and capability summary
- homepage comparison and feature sections
- architecture page “Design choices” and related cards
- shared section/card rhythm where needed

## Non-Goals

- complete site redesign
- introducing a multi-product IA
- changing the core content strategy
- dark mode or AWS-style brand imitation
